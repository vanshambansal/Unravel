## Confirmed causes and changes

- Removed pointer-following gradient lights from the private frame and each resource row. The authentication atmosphere now lives in a separate client module. Private chrome, tabs, evidence selection, SDK tabs and generator rows use ordinary elements instead of Motion layout/entrance animations. Removed nested internal backdrop filters and the report dialog backdrop blur. Task surfaces use stable charcoal fills. Button pressed feedback is immediate. Authentication retains its atmosphere and motion control. The marketing scene is outside this pass.
- Preserved the route template and made its wrapper static. Reports to Setup and back had retained the same template and shell during diagnosis. Next Activity retains inactive pages, so workflow tabs, replay range labels and dialog headings now have instance-specific IDs. Keyboard focus cannot select an older retained tab by a document-global ID.
- Removed the internal Next PrefetchKind import. Native full-prefetch Links own primary-route preparation. Secondary intent activates native full Link prefetch after a resource-policy check. Next owns request deduplication and cache lifetime; the workspace retains at most 24 intended URLs across page recreation, with no separate payload cache or manual prefetch request. Completed views remain visible during navigation. No experimental staleTimes or persistent private cache.
- SDK setup now obtains the owner-filtered project and an EXISTS report flag in one SQL statement. It previously awaited a project query and then read a paginated report list/count merely to show whether a report existed. A service regression covers missing identity, invalid IDs and foreign owners.
- Private GET reads now return numeric auth, connection, query/service and serialization Server-Timing stages. The existing plan endpoint retains its generation timing. Response contracts and no-store behavior remain. Timing data contains no identifiers, SQL, values or credentials.
- A controlled 125-second idle experiment compared the existing 120-second pool idle limit with a 300-second candidate. Existing pool retained zero clients and reacquisition took 575.1ms. Candidate retained one idle client and reacquisition took 0.7ms. Query times were 87.0/93.1ms. Adopted idle timeout300s and lifetime1800s, preserving max5 clients, connection timeout10s, TLS configuration and absence of background keepalive queries. First connections and provider/network disconnects can still be slow.
- PlanEditor is lazy loaded in the client boundary and prepared alongside its anticipated data read or tab intent. Once opened it remains mounted, with the inactive replay paused. Native inspector opening occurs before paint. JSON history/recovery/export semantics remain.
- Historic replay input matching now indexes captured inputs by node and caches repeated selector lookups. It preserves original ordering and matching windows while avoiding scanning all captured inputs for each action. Evidence is unchanged.
